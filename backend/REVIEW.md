# Starter-code review

| # | Where | What is wrong | How to notice | How it was fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It does not truncate timestamps to whole seconds before applying the grace rule, and its shift-date assumption is not explicit for overnight attendance. | Check the 09:40:00 / 09:40:01 boundary and a 03:00 IST punch on a 22:00-06:00 shift. | Normalize input timestamps and derive the attendance day per R1 before computing lateness. |
| 2 | `compute_overtime` | It anchors the shift end to the punch-out's calendar date and adjusts by a broad 12-hour heuristic, rather than the attendance date and overnight shift definition. | Punch out around an overnight shift boundary or compare with a shift ending next day. | Build shift end from the record's attendance date and shift times. |
| 3 | Index initialization | Index creation runs during module import, missing lifecycle ownership, and some required access paths are not indexed. | Importing the module touches MongoDB; inspect explain plans for filtered/sorted attendance. | Create named, idempotent indexes at app startup, covering attendance uniqueness, date/status listings, employee lookups and headcount queries. |
| 4 | Mongo error handling | The health endpoint catches every exception, turning programming errors into a misleading database 503. | Cause a non-database exception and observe the same response as a database outage. | Let unexpected errors surface; map PyMongo errors to 503. |
| 5 | `EmployeeIn` | Inputs have no contract-level validation for employee code, email, lengths, dates, shift formats, or equal shift times. | Submit malformed values or identical shift times. | Add typed request validation and explicit business validation. |
| 6 | `create_employee` | Check-then-insert is racy; a concurrent duplicate raises an uncaught database error. `created_at` is naive local time and is returned as a datetime, not epoch milliseconds. | Send simultaneous creates for one code and inspect storage/response types. | Enforce uniqueness with the index, map duplicate-key errors to 409, store UTC and serialize API timestamps as epoch milliseconds. |
| 7 | Punch request models | Pydantic coercion and missing bounds accept timestamp forms the contract rejects; punch-in's status is not restricted to presence statuses. | Send a seconds value, float, string, or `ABSENT` to punch-in. | Require bounded strict integer epoch milliseconds and a presence-status literal. |
| 8 | `punch_in` | It uses the current IST date even for the early-morning part of an overnight shift, stores BSON date fields as integer milliseconds, and check-then-insert can race. | Punch in at 03:00 IST on a 22:00-06:00 shift; inspect stored BSON; send duplicate concurrent requests. | Apply R1 date assignment, store UTC BSON datetimes and rely on the unique natural-key index with duplicate-key-to-409 handling. |
| 9 | `punch_out` | It searches only the punch-out's local date, so overnight records are missed. It does not enforce positive duration or the 24-hour ceiling, and a read/update race can return success twice. The response is incomplete. | Punch out after midnight, use equal/reversed/far-future timestamps, or race two requests. | Find the latest eligible punch-in across dates, validate the interval and atomically update only an open record; return the complete API record. |
| 10 | `list_attendance` | It omits the secondary `emp_code` sort, date validation and reversed-range rejection; it serializes only top-level times, not nested history times or legacy defaults. | Request equal dates with multiple employees, an invalid/reversed range, or a record with timestamp values in history. | Apply contract filters/sort and recursively serialize the API's timestamp fields, supplying legacy defaults. |
| 11 | `regularize_attendance` | It accepts an untyped dictionary, allows `half_day` even though it is derived, does not accept the contract's punch corrections/audit metadata, and does not recompute derived values. It also overwrites history and can lose concurrent edits. | Correct a punch and compare derived values/history; submit invalid fields; make overlapping corrections. | Validate the request, recompute all derived values, append only changed-field before/after values, and use compare-and-set to reject stale edits. |
| 12 | `employee_monthly_analytics` | It loads every matching document into Python, does not validate the month, ignores join date, weekdays, half-days and presence statuses, and returns the wrong fields. | Compare a mid-month join, weekend, WFH and half-day case with the schema; request an invalid month. | Use a MongoDB aggregation over a half-open month interval and compute working days from the employee's join date. |
| 13 | `department_summary` | The pipeline groups only employees with logs, has no month filter, and counts only `PRESENT`; it therefore loses zero-log headcount and excludes WFH/ON_DUTY presence. Its result schema is also incomplete. | Add an employee with no logs or seed WFH/ON_DUTY records. | Aggregate from eligible employees and left-lookup that month's logs, preserving empty log arrays. |
| 14 | `late_leaderboard` | It aggregates all-time data, truncates before resolving tied ranks, has no competition rank or department filter, and omits required response fields. | Compare two tied employees at the `limit` boundary and query different months. | Filter by month, calculate `$rank` after totals, then apply the rank cutoff and deterministic ordering. |
| 15 | `department_trend` | It accepts a month instead of the required date range, emits only dates with records, counts only `PRESENT`, and lacks headcount, rates, moving average and range/unknown-department errors. | Request a date with no logs or a weekend and verify every row/metric. | Generate daily rows inside MongoDB, lookup employee/log data and use a seven-row window. |
| 16 | `explain_endpoint` | It uses unrelated simplified pipelines, ignores several actual filters and required parameters, and therefore does not explain the main query executed by the named endpoint. | Compare the explain request pipeline/filters with the endpoint request, then inspect an execution plan. | Reuse the endpoints' query and aggregation builders, including filters, ordering, pagination and execution-stats verbosity. |

### Checked and not considered defects

- The unique `(emp_code, date)` attendance index is the right concurrency guarantee; the defect was not catching its duplicate-key error.
- Treating naive BSON datetimes as UTC is appropriate for this data model. The starter's inconsistency between UTC instants, IST calendar dates and integer storage was the problem.
- Half-up rounding through `Decimal` is correct; the replacement retains it and applies it to analytics output as well.
